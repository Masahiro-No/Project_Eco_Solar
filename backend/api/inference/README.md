# Inference Module (`backend/api/inference`)

สร้างข้อมูลป้อน LSTM จาก `weather_history` ส่งงานพยากรณ์เข้าคิว บันทึกผลที่ worker คืนมา และให้หน้าเว็บอ่านผลพยากรณ์ ตัวโมเดลรันใน `inference-worker` (ดู `service/workers/`) ไม่ได้รันใน API

| Method | Endpoint | ใช้ทำอะไร | ใครเรียกได้ |
|---|---|---|---|
| `GET` | `/api/inference/latest/{station_id}` | ผลพยากรณ์รอบล่าสุด (หน้าแรกใช้) | ผู้ใช้ที่ล็อกอิน |
| `GET` | `/api/inference/history/{station_id}` | ผลพยากรณ์ย้อนหลัง | ผู้ใช้ที่ล็อกอิน |
| `GET` | `/api/inference/predictions-by-date` | ผลของทั้งวันเรียงตามเวลาจริง พร้อมค่าวัดจริงและ MAE เลือกระยะล่วงหน้าได้ด้วย `lead_minutes` | ผู้ใช้ที่ล็อกอิน |
| `POST` | `/api/inference/predict` | สั่งพยากรณ์สถานีหนึ่งทันที | admin |
| `GET` | `/api/inference/result/{job_id}` | ผลของงานที่สั่งไว้ | ผู้ใช้ที่ล็อกอิน |

## กติกาสำคัญ

- **ช่อง 10 นาที** `weather_grid.py` จัดแถวสภาพอากาศลงช่อง 10 นาทีแบบเดียวกับตอนเทรน ช่องว่างไม่เกิน 20 นาทีเติมเชิงเส้น ยาวกว่านั้นไม่พยากรณ์และบันทึกเหตุผล (`gap_in_history`, `insufficient_history`, `stale_data`)
- **หนึ่งผลต่อสถานีต่อช่อง 10 นาที** ชื่องานเป็น `infer-<สถานี>-<ช่องเวลา>` รอบที่ถูกสั่งซ้ำจึงรันครั้งเดียว
- **มุมมองทั้งวัน** ช่องเวลาที่ผ่านไปแล้วใช้ผลของรอบที่ทำนายล่วงหน้าตามระยะที่เลือก ช่องอนาคตใช้รอบล่าสุด

## ไฟล์

- `service.py` สร้างข้อมูลป้อน ส่งงาน เก็บผล และมุมมองทั้งวัน
- `weather_grid.py` กฎช่อง 10 นาที (ไม่มีฐานข้อมูล ตรวจแยกได้)
- `persistence.py` บันทึกผลของ worker ลงตาราง `predictions` (ทำซ้ำได้โดยไม่เกิดแถวซ้ำ)
- `model.py` ตาราง `predictions`, `schema.py`, `controller.py`, `router.py`
