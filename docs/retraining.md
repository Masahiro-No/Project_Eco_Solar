# การ retrain

[← กลับไปที่ README](../README.md) · [เอกสารทั้งหมด](README.md)

ทั้งสองโมเดลเรียนต่อจากข้อมูลจริงของระบบ และโมเดลใหม่ถูกนำไปใช้เมื่อผ่านเกณฑ์เท่านั้น โค้ดอยู่ใน [service/training/](../service/training/README.md)

เปิดปิดด้วย `ENABLE_RETRAIN` ใน `.env` (ค่าเดียวใช้กับทั้งสองโมเดล) ทั้งสองแบบสำรองไฟล์เดิมก่อนแทนที่ และแทนที่เฉพาะเมื่อโมเดลใหม่ผ่านเกณฑ์บนข้อมูลที่กันไว้ตรวจ

| | LSTM | ConvLSTM |
|---|---|---|
| เริ่มเมื่อ | มีค่า GHI ที่วัดจริงของวันใหม่ครบ 7 วัน (บันทึกที่หน้าบันทึกค่าวัดจริง) | มีภาพดาวเทียมกลางวันใหม่ครบ 50 เวลาสแกน |
| ข้อมูล | ข้อมูลป้อนจาก `weather_history` 45 วันล่าสุด แบบเดียวกับตอนพยากรณ์จริง เป้าหมายคือค่า GHI ที่วัดจริง | ภาพจริงใน MinIO 5 วันล่าสุด ตัดเป็นชุด 30 เฟรมต่อเนื่อง (12 → 18) |
| น้ำหนักเริ่มต้น | จากไฟล์ ONNX ที่ใช้งานอยู่ | จากไฟล์ ONNX ที่ใช้งานอยู่ |
| เกณฑ์ผ่าน | MAE เทียบกับ GHI ที่วัดจริง บนวันที่โมเดลที่ใช้งานอยู่ยังไม่เคยเทรน ลดลงอย่างน้อย 3% (ดูด้านล่าง) | MSE บนชุดตรวจ (ช่วงเวลาล่าสุด) ไม่สูงกว่าเดิม |
| รอบที่ผ่านล่าสุด (5 ต.ค. 2026) | v1.1.0 → v1.1.1, MAE 33.5 → 25.3 W/m² (452 windows, ผ่านด้วยเกณฑ์เดิม) | v1.0.1 → v1.0.2 เวลา 17:25 น. เริ่มเองเมื่อภาพครบ 50 เวลาสแกน: MSE 0.0088 → 0.0081, SSIM 0.57 → 0.63, ความคลาดเคลื่อนของ % เมฆในกรอบ 19.9 → 15.9 จุด (39 ชุด, 654 เฟรม; ตัดภาพที่ผู้ดูแลปฏิเสธ 2 ภาพ) |

**วิธี retrain ของ LSTM** (เปลี่ยนเมื่อ 6 ต.ค. 2026) โมเดลเรียนและถูกตรวจในเงื่อนไขเดียวกับตอนใช้งาน และรอให้ค่าวัดจริงสะสมก่อน

- **สะสมก่อน** ทุกครั้งที่บันทึกค่าวัดจริง ระบบนับวัน (เวลาไทย) ที่มีค่าวัดจริงซึ่งรอบ retrain ก่อนหน้ายังไม่เคยใช้ ครบ 7 วัน (`RETRAIN_MIN_NEW_DAYS` ของ `trainer-worker` ใน `compose.yml`) จึง retrain หนึ่งรอบ นับตามวันที่ของข้อมูล ไม่นับจำนวนไฟล์: สองสถานีในวันเดียวกันนับเป็นหนึ่งวัน วันที่มีค่าวัดไม่ถึง 6 ช่อง (1 ชั่วโมง) ยังไม่นับ หน้า *สถานะ retrain* แสดงจำนวนที่นับได้ (เช่น 3 / 7 วัน) ซึ่งอัปเดตราว 5 นาทีหลังบันทึก
- **ข้อมูลป้อน** ของทุก window มาจาก `weather_history` อย่างเดียว แบบที่โมเดลได้รับตอนพยากรณ์จริง ค่าที่วัดจริงไม่ถูกเขียนลงในข้อมูลป้อน เพราะตอนใช้งานค่านั้นยังมาไม่ถึง (ผู้ดูแลอัปโหลดเป็นไฟล์ทีหลัง)
- **เป้าหมาย** คือ GHI ที่วัดจริงของช่วงพยากรณ์ และ loss คิดเฉพาะช่องที่มีค่าวัดจริงตอนกลางวัน
- **เทรนด้วยทุกวันที่สะสมได้** ทุกรอบใช้ค่าวัดจริงทั้งหมดในช่วง 45 วันล่าสุด (`RETRAIN_LOOKBACK_DAYS`) ไม่ใช่เฉพาะวันใหม่: รอบแรก 7 วัน รอบถัดไป 14 วัน และเพิ่มไปเรื่อย ๆ
- **ตรวจบนวันที่โมเดลที่ใช้งานอยู่ยังไม่เคยเทรน** (cross-validation ตามวัน) เมื่อโมเดลใหม่ถูกนำไปใช้ ระบบจดวันที่โมเดลนั้นเทรนไปแล้วไว้ใน `model_meta.json` (`retrain.trained_days`) รอบถัดไปใช้วันเหล่านั้นเทรนต่อได้ แต่ไม่ใช้ตรวจ วันที่เหลือถูกแบ่งเป็นไม่เกิน 7 กลุ่ม (`RETRAIN_CV_FOLDS`; มีไม่เกิน 7 วันคือกันทีละวัน) แต่ละกลุ่มถูกกันไว้ตรวจหนึ่งครั้ง โดยเริ่มจากโมเดลที่ใช้งานอยู่แล้ว fine-tune จากวันที่เหลือทั้งหมด ได้ MAE เทียบค่าวัดจริงรวมทุกวันที่ตรวจของแต่ละ epoch ถ้ารอบก่อนไม่ผ่าน วันของรอบนั้นยังเป็นวันที่โมเดลไม่เคยเทรน รอบถัดไปจึงตรวจได้ 14 วัน
- **เกณฑ์รับ** ใช้ epoch ที่ MAE รวมต่ำสุด โมเดลใหม่ถูกใช้เมื่อ MAE รวมนั้นต่ำกว่าของโมเดลเดิมอย่างน้อย 3% (`RETRAIN_MIN_IMPROVEMENT`) เมื่อผ่าน ระบบเทรนจากทุกวันด้วยจำนวน epoch นั้นแล้วนำไปใช้ MAE เทียบกับค่าของ Open-Meteo ยังบันทึกไว้ให้ดูประกอบ แต่ไม่ใช้ตัดสิน
- รอบที่รันแล้ว ทั้งที่นำไปใช้และไม่นำไปใช้ ทำให้ตัวนับกลับเป็น 0 รอบถัดไปเกิดเมื่อมีวันใหม่ครบอีก 7 วัน

**เหตุที่สะสมและตรวจจากหลายวัน** เดิมระบบ retrain ทุกครั้งที่บันทึกค่า และตัดสินด้วยวันล่าสุดวันเดียว ผลที่วัดได้ (ตารางใน [experiments](experiments.md) หัวข้อ *การ retrain LSTM จากค่าวัดจริง*): โมเดลที่เทรนด้วย 6 วันเหมือนกัน ถ้าตัดสินด้วยวันที่ 5 ต.ค. ดีขึ้น 13% ถ้าตัดสินด้วยวันที่ 4 ต.ค. แย่ลง 41% ทั้งที่รวมทุกวันแล้วเท่าเดิม คำตัดสินจากวันเดียวจึงขึ้นกับสภาพอากาศของวันนั้น ไม่ใช่กับโมเดล และการเทรนด้วยค่าวัดจริง 1–4 วันให้ผลแย่กว่าโมเดลเดิม

**เหตุที่ไม่ตรวจบนวันที่โมเดลเคยเทรน** โมเดลดูดีกว่าความจริงบนวันที่เคยเห็นคำตอบ จำลองสองรอบจาก 7 วันที่มี: โมเดลที่เทรนด้วย 4 วันแรกได้ MAE 146.9 W/m² บน 4 วันนั้น แต่ถ้าเว้นวันที่วัดไว้ไม่ให้เทรนจะได้ 176.2 (ดูดีเกินจริง 17%) ถ้ารอบถัดไปตรวจบนทุกวัน โมเดลที่ใช้งานอยู่จึงได้เปรียบและโมเดลใหม่ไม่ผ่าน (128.8 → 128.8) ขณะที่บน 3 วันที่ไม่มีโมเดลไหนเคยเห็น โมเดลใหม่ดีกว่า 5.6% (104.3 → 98.5)

**เหตุที่เปลี่ยนข้อมูลป้อนและเกณฑ์** วิธีแรก (5 ต.ค.) มีสองจุดที่ทำให้ผลตรวจไม่ตรงกับการใช้งาน ตัวเลขอยู่ใน [experiments](experiments.md) หัวข้อ *การ retrain LSTM จากค่าวัดจริง*

1. ค่าที่วัดจริงถูกเขียนทับลงในคอลัมน์ GHI ซึ่งเป็นทั้งข้อมูลป้อนและเป้าหมาย ตอนตรวจ โมเดลจึงเห็นค่าวัดจริงในช่วงย้อนหลัง ซึ่งตอนพยากรณ์จริงไม่มี โมเดลเดียวกันที่ระยะ 10–30 นาทีได้ MAE 118.7 W/m² เมื่อตรวจแบบเดิม แต่ได้ 140.1 เมื่อป้อนแบบใช้งานจริง
2. เกณฑ์ข้อที่สองห้ามแย่ลงเกิน 5% บนชุดตรวจที่เป้าหมายเป็นค่าของ Open-Meteo ทั้งที่การเรียนจากค่าวัดจริงคือการขยับออกจากค่าของ Open-Meteo และเมื่อมีค่าวัดจริงวันเดียวก็ใช้เกณฑ์สำรองที่วัดกับค่าของ Open-Meteo อย่างเดียว

**ผลของวิธีใหม่** รอบจริงผ่านคิวเวลา 19:48 น. วันที่ 6 ต.ค. 2026: มีค่าวัดจริงของวันใหม่ 7 วัน (29 ก.ย.–5 ต.ค., ST-002 และ ST-003) จึง retrain กันทีละวันครบ 7 วัน รวม 7,452 จุด MAE เทียบค่าวัดจริง 138.1 → 137.4 W/m² ที่ epoch 8 ดีขึ้น 0.5% ไม่ถึงเกณฑ์ 3% ระบบไม่แทนที่โมเดล (`no_improvement_on_measured_ghi`) งานถัดมาในคิวนับได้ 0 / 7 วัน จึงจบโดยไม่ retrain (`waiting_for_more_days`)

ความหมายของผลนี้: ด้วยค่าวัดจริง 7 วันจาก 2 สถานี การ fine-tune ยังไม่ทำให้โมเดลแม่นขึ้นในการใช้งานจริง โมเดลคลาดเคลื่อนใกล้เคียงกับข้อมูลป้อนของมันเอง (ค่า GHI ของ Open-Meteo คลาดจากค่าวัดจริง 143.0 W/m² ส่วนผลพยากรณ์ของโมเดลคลาด 138.1) ซึ่งการปรับน้ำหนักโมเดลแก้ไม่ได้ คำตอบว่า "ไม่ดีขึ้น" จึงตรงกับข้อมูล และจะเปลี่ยนเองเมื่อค่าวัดจริงที่สะสมได้ทำให้โมเดลใหม่ดีกว่าจริง

ก่อนหน้านั้นในวันเดียวกัน (19:21 น.) มีหนึ่งรอบที่ป้อนข้อมูลแบบใช้งานจริงแล้วแต่ยังตัดสินด้วยวันเดียว (กันวันที่ 5 ต.ค., ใช้วันที่ 4 ต.ค. เลือก epoch): 133.3 → 133.3 W/m² ไม่แทนที่โมเดล

**รอบของวิธีแรก** (5 ต.ค.) MAE เทียบค่าวัดจริงของรอบเหล่านี้วัดโดยมีค่าวัดจริงอยู่ในข้อมูลป้อน จึงเทียบกับตัวเลขของวิธีใหม่ไม่ได้ เกณฑ์ตอนนั้นคือ ลด MAE เทียบค่าวัดจริงของวันที่กันไว้ และ MAE บนชุดตรวจที่ไม่มี label แย่ลงได้ไม่เกิน 5% (มี label วันเดียว: MAE บนชุดตรวจไม่สูงกว่าเดิม) ผลบันทึกว่าใช้เกณฑ์ใด (`gate`), วันที่กันไว้ (`holdout_day`) และ MAE ก่อนหลัง รอบที่ลองด้วยเกณฑ์ใหม่บ่ายวันที่ 5 ต.ค. (กันวันที่ 5 ต.ค. ไว้ 315 จุด) MAE เทียบกับค่าวัดจริงเดิม 56.8 W/m² และไม่ดีขึ้นหลัง fine-tune ระบบจึงไม่แทนที่โมเดล (`no_improvement_on_measured_ghi`) รอบ 18:26 น. หลังเพิ่มค่าวัดจริงของ ST-003 (ค่าวัดจริงรวม 679 ช่อง) MAE เทียบกับค่าวัดจริงดีขึ้น 103.2 → 97.0 W/m² แต่ MAE บนชุดตรวจที่ไม่มีค่าวัดจริงแย่ลง 30.4 → 37.2 (เกิน 5%) ระบบจึงไม่แทนที่โมเดลเช่นกัน (`worse_on_weather_only_validation`) รอบ 17:29 น. วันที่ 6 ต.ค. ซึ่งเริ่มเองหลังบันทึกค่าวัดจริงและยังเป็นวิธีเดิม ให้ผลแบบเดียวกัน (99.3 → 87.3 และ 29.6 → 32.6) หน้า *สถานะ retrain* ใส่เครื่องหมาย * ที่ MAE เทียบค่าวัดจริงของรอบที่ตรวจด้วยวิธีเดิม

ทุกรอบของทั้งสองโมเดล ทั้งที่นำไปใช้และไม่นำไปใช้ ดูได้ที่หน้า *สถานะ retrain* (ผู้ดูแล) ซึ่งอ่านประวัติจาก MLflow: ถึงเย็นวันที่ 5 ต.ค. 2026 LSTM มี 6 รอบ (นำไปใช้ 1) และ ConvLSTM มี 3 รอบ (นำไปใช้ทั้ง 3)

**กราฟการเรียนรู้ราย epoch** ทุกรอบ retrain บันทึกค่าของแต่ละ epoch ลง MLflow เป็น metric ชื่อ `epoch_*` (step = epoch): loss บนข้อมูลเทรน ค่าคลาดเคลื่อนบนข้อมูลตรวจ (LSTM ใช้ MAE, ConvLSTM ใช้ MSE และ SSIM) และ learning rate โดย epoch 0 คือโมเดลที่ใช้งานอยู่ก่อนเริ่มรอบ หน้า *สถานะ retrain* วาดเป็นกราฟต่อรอบและขีดเส้นที่ epoch ที่ดีที่สุด ใช้ดูว่าโมเดลลู่เข้าหรือเริ่มจำข้อมูลเทรน (แนวคิดเดียวกับ TensorBoard ในเนื้อหารายวิชา แต่ใช้ MLflow ที่ระบบมีอยู่แล้ว) รอบแรกที่มีกราฟคือ LSTM เวลา 20:45 น. วันที่ 5 ต.ค. 2026: loss ลดจาก 0.00383 เป็น 0.00355 ใน 6 epoch ส่วน MAE บนข้อมูลตรวจลดจาก 100.5 เป็น 88.8 W/m² ที่ epoch 3 แล้วไม่ดีขึ้นอีก รอบก่อนหน้านั้นไม่ได้เก็บค่าราย epoch จึงไม่มีกราฟ โค้ด: [service/training/curves.py](../service/training/curves.py)

**คนอยู่ในวงจรทั้งสองโมเดล:** LSTM ใช้ค่า GHI ที่วัดจริงซึ่งผู้ดูแลอัปโหลดหรือกรอกที่หน้า *บันทึกค่าวัดจริง* ส่วน ConvLSTM เรียนจากการทำนายภาพถัดไป คำตอบจึงเป็นภาพจริงเอง สิ่งที่คนเพิ่มได้คือการตรวจว่าภาพไหนใช้ไม่ได้ ที่หน้า *ตรวจภาพดาวเทียม* ผู้ดูแลเห็นภาพจริงรายวันพร้อมข้อสังเกตอัตโนมัติ (ภาพดำ, ภาพขาดบางส่วน, สว่างจ้า, ความสว่างกระโดด) แล้วกดว่าใช้ได้หรือใช้ไม่ได้ ภาพที่ถูกปฏิเสธจะไม่เข้าชุดเทรนรอบถัดไป หน้าเดียวกันแสดงจำนวนภาพใหม่ที่สะสม (x/50) รุ่นโมเดล และผล retrain รอบล่าสุด ค่า GHI ที่วัดจริงยังใช้ปรับสูตรแปลงภาพเป็นแสงด้วย ([calibration](calibration.md))

label ที่บอกว่ามีแดดตอนกลางคืนจะไม่ถูกใช้ ผลทุกรอบบันทึกใน MLflow (`solar_lstm_retrain`, `solar_convlstm_retrain`)
ตัวเลขข้างบนวัดบนข้อมูล 4–8 วันล่าสุดของระบบนี้ ยังไม่ใช่ผลระยะยาว

```bash
docker exec trainer-worker sh -c 'cd /workspace && python -m service.training.retrain_convlstm --status'
```
